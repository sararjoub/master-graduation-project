# خطة الباك إند المعتمدة - Skills Swap

## القرارات الوظيفية

- اختيار مهارات التعلم اختياري، واختيار مهارات التعليم اختياري ومستقل عنه. يمكن للمستخدم تخطي قسم التعليم وإضافة مهارة تعليم لاحقاً.
- طلب التعلم يربط متعلماً بمعلّم ومهارة واحدة، ولا يشترط أن يقدم المتعلم مهارة مقابلة ولا أن يتعامل مع الشخص نفسه لاحقاً.
- المستخدم العادي يستطيع عرض نفسه لتعليم مهارة. صفة «خبير معتمد» منفصلة وتمنح لكل مهارة بعد طلب ومراجعة أدمن موثقة.
- Plus لا يحول المستخدم إلى خبير. Plus يفتح محتوى Advanced وحجز جلسة خبير حسب الرصيد والسياسة.
- المحادثة واللقاء متاحان فقط لطرفي طلب مقبول. الأدمن لا يقرأ محتوى المحادثة أو الاجتماع.
- مسار AI يبدأ Draft، ثم UnderReview. لا يظهر كمسار نهائي ولا يصبح Active قبل موافقة الأدمن.
- إنجاز خطوة المسار يفتح الخطوة التالية فقط. إثبات الإنجاز والـquiz يضافان بعد تثبيت المحتوى وآلية التقييم.

## ما تم تأسيسه

- ASP.NET Core Identity بمفاتيح Guid، بريد فريد، تأكيد بريد إلزامي، وقفل بعد محاولات دخول فاشلة.
- EF Core Code First وSQL Server مع أول Migration وسكربت SQL قابل للتطبيق.
- التصنيفات، التصنيفات الفرعية، المهارات، ومهارات المستخدم Learn/Teach.
- طلبات اعتماد الخبراء وتوفرهم لكل مهارة.
- Free/Plus والاشتراكات والمدفوعات.
- طلب تعلم مباشر، جلسة، محادثة، وتقييم.
- مسار مهني وحالات مراجعة وخطوات متسلسلة مع Free/Plus لكل خطوة.

## حدود JavaScript

يبقى JavaScript للأنيميشن والتفاعل البصري والنوافذ وSignalR وZoom SDK عند الحاجة. يجب نقل `localStorage` والبيانات التجريبية ومنطق الصلاحيات والاشتراك والتقدم إلى Controllers/Services/Database. كل قرار وصول يعاد التحقق منه على السيرفر.

## ترتيب التنفيذ التالي

1. التسجيل والدخول وتأكيد البريد وإكمال الملف الشخصي.
2. CRUD التصنيفات والمهارات للأدمن، وعرضها من قاعدة البيانات للمستخدم.
3. اختيار Learn وتعليم اختياري وربط صفحة الشركاء بنتائج حقيقية.
4. الطلبات والمحادثة عبر SignalR مع تفويض الطرفين.
5. اعتماد الخبراء والتوفر والحجز.
6. المسارات: توليد Ollama كمسودة، مراجعة الأدمن، التفعيل، والتقدم المتسلسل.
7. Plus والدفع الحقيقي ثم Zoom، بعد تحديد المزود واستلام الإعدادات.
8. التقييمات والبلاغات المحسومة والاختبارات والتقارير.

## ملاحظات تشغيل

- الاتصال الافتراضي حالياً بـ SQL Server على `localhost` وقاعدة Code First الجديدة `SkillsSwapCodeFirst`، بينما تبقى قاعدة `SkillsSwap` القديمة مستقلة.
- لا توضع أسرار البريد أو Zoom أو الدفع أو Ollama داخل المستودع؛ تستخدم User Secrets أو متغيرات البيئة.
- ملف SQL القديم مرجع للبيانات والأفكار، وليس schema نهائياً، لأنه ما زال يحتوي أنواع Exchange/Volunteer التي لم تعد مطلوبة.
